Problem Statement

Factory telemetry at scale is hard

Modern auto plants generate millions of sensor readings per hour across heterogeneous protocols, with zero tolerance for data loss during network blips.

📡 Protocol Chaos

PLCs speak MQTT + Protobuf. Legacy lines use OPC UA. Each protocol needs a dedicated adapter and schema contract.

⚡ Volume & Velocity

High-frequency streams overwhelm naive ingest paths. Backpressure, worker pools, and adaptive sampling are mandatory.

🛡 Resilience Required

Kafka outages, DB latency spikes, and validation failures must not drop data — spool locally, route to DLQ, degrade gracefully.

SentinelFlow's answer

A layered pipeline — edge ingest → stream validation → time-series persistence → GraphQL Digital Twin API — with observability baked in from day one.

Architecture

Layered stream processing

Edge adapters normalize heterogeneous inputs into a single Kafka raw topic. Stream processors validate, detect anomalies, and route to processed or DLQ topics.

06 / 07
Reliability

Built for production hiccups

SentinelFlow assumes infrastructure fails. Every layer has a fallback path — no silent data loss at the edge.

💾

Local spooling (BadgerDB)

Kafka outage? Edge data spools locally until the broker recovers — zero loss.

📋

Dead-letter queue

Validation failures and anomalies route to a replayable DLQ — observable and recoverable.

⚡

Redis fallback

When TimescaleDB write latency spikes, hot keys serve from Redis cache.

🔄

Adaptive sampling & circuit breakers

Under sustained load, sampling adapts and breakers prevent cascade failures.

🛑

Graceful shutdown

In-flight messages drain cleanly on SIGTERM — no orphaned batches.

📊

CI on every push

Go lint + test for ingestion & stream-processor. TS lint + test for persistence & graphql-api.
